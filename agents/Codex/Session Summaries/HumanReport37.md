## Decisions on Claude's four questions

### Per-cell Stage-C rule approved

I approved the operative rule:

```text
pass(v) iff D(v,c) >= 2 * Q95_c for every screened cell c
```

It compares each cell's structural signal with that cell's own run-to-run
healthy null. The stricter scalar rule:

```text
min_c D(v,c) >= 2 * max_c Q95_c
```

should remain a predeclared sensitivity analysis, not a second success route.

### Eight healthy replicates per cell approved

I approved increasing Stage C from six to eight healthy runs per cell. The
additional eight rollouts are proportionate and move a conservative empirical
95th percentile off the maximum, provided the exact finite-sample quantile
method is pinned.

The limitation remains explicit: 28 pairwise distances are generated by only
eight independent runs and therefore are dependent.

### Torque pruning approved as reporting

The full 3-by-8 candidate grid remains declared. Applying the already-approved
inclusive torque gate before simulation is evaluation of that grid, not an
amendment of it.

I approved:

```text
F_peak * 2 * link_length_m <= 0.60 * torque_abs_limit[0]
```

The inclusive boundary retains 0.15 N exactly, excludes the five higher
amplitudes at all three ramp fractions, and leaves a 108-rollout Stage-A worst
case.

### Severity rebalancing rejected

I rejected changing severity-to-split allocations now. Existing development
mechanics evidence already points toward the severe end, so reallocating values
to ensure detectable examples in particular roles would be outcome-informed in
the direction that could favor S.

The approved prospective policy is to preserve the role-owned severities and
compute known-class testable structural coverage separately for dev, pilot,
validation, and test:

- zero dev coverage means no testable structural training support;
- zero validation coverage means the structural part of
  selection/calibration is unsupported;
- zero test coverage makes the proposed four-way confirmatory testable-stratum
  metric undefined;
- any of those three zeroes creates a named role-coverage-bounded non-transfer
  outcome. S/C1 analyses may still be secondary, but the branch cannot establish
  full success or hypothesis failure;
- zero pilot coverage cannot relabel settings. It disables data-driven
  structural-stratum downsizing, retains the prospectively allowed maximum test
  replication, and becomes a named limitation.

This answers the open question before the ladder without selecting the
confirmatory population toward forecasted detectability.

## Why proposal v4 remains blocked

### Failed safety branches cannot carry failed probes forward

The proposed `NO_ADMISSIBLE_PROBE` branch says that if all 24 candidates fail a
hard safety gate, the amendment should retain the 0.05 N / ramp-0.5 probe and
proceed to regeneration.

That probe is itself one of the 24. In the branch as defined, it has failed.
The protocol cannot call it safe merely because already-delivered runs make the
branch unlikely.

The required action is terminal and conservative:

- keep `config.json` absent;
- authorize no regeneration;
- treat the occurrence as a safety/method or implementation-integrity failure;
  and
- diagnose it or write a new same-state-reviewed fallback amendment.

Stage B has the same categorical problem. `unsafe_at_severity` is neither
`TESTABLE` nor `SUB-THRESHOLD`; it lacks an admissible M2 verdict. An unsafe
value must trigger a separate terminal method/safety branch. Cases A/B/C are
available only after all ten values receive safe, valid M2 verdicts.

### The decision-bearing quantile estimator is not pinned

At these sample sizes, "95th percentile" does not identify one number. Under
NumPy 2.5.1, 28 sorted values produce:

```text
method="linear": 26.65th ordered-value coordinate
method="higher": 27th order statistic
```

For 15 values, `method="higher"` is the maximum. Claude's eight-replicate
rationale therefore depends on the method.

I required:

```python
Q95_c = np.quantile(within_cell_distances, 0.95, method="higher")
```

with the same method used for descriptive pooled and stricter-sensitivity
quantities.

### The CRN-collapse explanation is inconsistent with the code

`Reproducibility Packet/scripts/utils/rng.py:76-78` constructs every generator
from:

```text
(sensor_seed, pair_id, channel, stream)
```

Changing either `sensor_seed` or `pair_id` changes the generator. Only reusing
the complete `(sensor_seed, pair_id)` pair collapses a replicate onto the same
substreams. Stage 0 itself fixes `pair_id=1`, varies `sensor_seed`, and produces
a nonzero difference null.

The proposed identity table remains good. The implementation must
deterministically assert:

- all eight `(sensor_seed, pair_id)` tuples are unique within each Stage-C cell;
- k=0 exactly matches the selected Stage-A healthy identity; and
- k=1..7 are distinct from k=0 and from one another.

The proposed `Q95_c >= 0.30 microstrain` tripwire may remain a diagnostic pause,
but not an identity proof or scientific gate. A realized vector distance is not
mathematically lower-bounded by the sensor-only reference because components
can cancel.

### The observed-data reduction and Stage-0 output path are incomplete

The shared `harmonic_coefficients` function requires the signal, validity mask,
measurement times, and frequency. Protocol P must pin the actual reduction:

```python
b_g = harmonic_coefficients(
    gauge_obs[:768, g],
    gauge_valid[:768, g],
    gauge_measurement_time_s[:768],
    0.8,
)
```

using one exact onset/index convention across Stages 0/A/B/C. This prevents
dropout and the two-millisecond gauge measurement grid from becoming later
analyst choices.

The posted command starts from the repository root but uses
`--output-dir results/protocol_p`, which would create a root-level output rather
than the named packet artifact. From the repository root it must use:

```text
--output-dir "Reproducibility Packet/results/protocol_p"
```

or give an exact packet-directory command with the corresponding parent-relative
venv path.

### Thermal insensitivity is measured; exact cancellation is overstated

Claude's measured near-invariance across 0–3 °C is useful. The stated mechanism
is too absolute.

`sensor_model.py:429-431` adds thermal, bias, drift, and noise and then quantizes
their sum at 0.5 microstrain. The shared deterministic linear thermal term is
removed by the intercept/trend fit and matched differencing in exact
unquantized arithmetic, but quantization prevents literal samplewise exact
cancellation. The next text should report measured insensitivity and the
first-order mechanism, not exact cancellation.
